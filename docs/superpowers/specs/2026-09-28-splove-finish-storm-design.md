# СПLOVE: финиш, таблица по времени и погода «Шторма»

Дата: 2026-09-28. Этапы 2 и 3 из `2026-09-28-splove-stages-design.md`. Решения согласованы с Виктором: финиш на каждой сложности, две таблицы («Очки» и «Время»), «Шторм» с лимитом времени, боковым ветром и дождём; время вышло без финиша — заплыв заканчивается, очки сохраняются, в «Время» не попадает.

## Этап 2. Финиш и таблица по времени

### Правила

- **Дистанции:** Прогулка 3000 м, Сплав 4000 м, Шторм 5000 м. Лежат в одном объекте `FINISH_M` в игре и такой же таблице на сервере.
- **Финиш** — линия на `s0 + FINISH_M[level]` метров, рисуется как ворота. Пересёк — заплыв закончен, очки на воде **сдаются в лагерь автоматически**, показывается экран «Финиш» со временем и очками.
- **Время** — время симуляции `simT` (пауза не идёт), в миллисекундах. Возвраты в лагерь время не обнуляют: они бесплатными не бывают.
- **Лагеря и ступени** не меняются. Финиш не считается лагерем: `st.camps` не растёт.
- **Заплыв недели** на «Сплаве» тоже имеет финиш 4000 м. Таблица недели остаётся по банку.
- Заплыв без финиша (без вёсел, без возвращений, время вышло на «Шторме») заканчивается как сейчас.

### Данные и сервер

Миграция `0009_finish.sql`:

```sql
ALTER TABLE runs ADD COLUMN finished INTEGER NOT NULL DEFAULT 0;
ALTER TABLE runs ADD COLUMN time_ms  INTEGER;

CREATE TABLE best_times (
  tg_id INTEGER NOT NULL, level TEXT NOT NULL CHECK (level IN ('easy','normal','hard')),
  time_ms INTEGER NOT NULL, run_id INTEGER NOT NULL, updated_at INTEGER NOT NULL,
  PRIMARY KEY (tg_id, level)
);
```

- Клиент присылает `finished: true` и `timeMs`. Сервер принимает финиш, только если одновременно: `meters >= FINISH_M[level]`, заплыв не отклонён, `timeMs` — целое от 1 до `durationMs + 2000`, и `timeMs >= FINISH_M[level] / MAX_MPS * 1000` (быстрее физики нельзя). Иначе финиш молча снимается (`finished = 0`), сам заплыв засчитывается как обычный.
- Принятый финиш обновляет `best_times` (меньше время — рекорд; при равенстве остаётся прежний).
- **Таблица «Время»:** `POST /api/board { level, kind: 'time' }`, топ-20 по возрастанию времени, при равенстве выше тот, кто финишировал раньше, забаненные скрыты, место игрока. `kind` по умолчанию `'points'` (как сейчас).
- Ответ `/api/runs` для финиша получает `finish: { timeMs, isRecord, rank }`.
- Максимум очков на метр (`MAX_POINTS_PER_METER = 30`) не меняется: автосдача не создаёт очков.

### Игра

- Ворота и экран финиша на канвасе; при финише `state = 'finish'`, вызывается `finishRun` с `finished: true` и `timeMs`.
- Меню: в кнопках сложности видна дистанция («3 км», «4 км», «5 км»).
- Экран рейтинга: переключатель «Очки / Время» над вкладками сложностей; время показывается как `м:сс,д`.
- Экран финиша: время, очки, место в таблице «Время», кнопки «Ещё раз» и «Рейтинг».
- Рамка процесса: HUD показывает оставшуюся дистанцию до финиша.

## Этап 3. Погода «Шторма»

Только на сложности «Шторм». Все случайные величины детерминированы от зерна заплыва (нужно, чтобы симуляцию можно было повторить), `Math.random()` только в косметике.

- **Лимит времени:** 330 секунд симуляции. Таймер идёт назад в HUD, последние 30 секунд красный. Время вышло без финиша — заплыв заканчивается («Время вышло»), очки, сданные в лагерь, и очки на воде идут в таблицу «Очки», в «Время» не попадают. Возврат в лагерь доступен, пока не вышло время.
- **Боковой ветер:** порывы каждые 10–18 секунд, длительность 3–5 секунд. Сила по формуле `40·U·(1 + 0.08·min(ступень, cap))` px/с в сторону, направление чередуется по зерну. За 1,5 секунды до порыва предупреждение: надпись «Порыв слева/справа», звук, штрихи на воде. Во время порыва к скорости лодки добавляется боковая составляющая; при рывке (`двумя пальцами`) сопротивление выше.
- **Дождь:** визуально капли и рябь на всём экране. Механика: управление слабее на 15% (`av`-импульс ×0.85). Дождь идёт весь заплыв.
- **Нулевая ступень и другие сложности** не меняются: всё выше включается только при `LV === 'hard'`, и без включённых условий ни один вызов `rnd()` не добавляется. Эталон `tests/sim/golden-stage0.json` для «Прогулки» и «Сплава» обязан совпадать; для «Шторма» эталон обновляется осознанно и коммитится вместе с описанием причины.
- **Сервер:** заплыв «Шторма» с `durationMs` больше 330 секунд плюс запас отклоняется как `bad_numbers`; `finished` на «Шторме» принимается только при `timeMs <= 330000`.

## Проверка

- Симуляция (Node): финиш срабатывает на нужном метре, очки сдаются, время равно `simT`, возвраты в лагерь время не сбрасывают, пауза его не увеличивает, «Шторм» заканчивается по лимиту, ветер и дождь детерминированы и действуют только на «Шторме», предупреждение приходит за 1,5 с.
- Воркер: финиш принимается и отклоняется по правилам, рекорд времени, таблица «Время» (порядок, тай-брейк, забаненные), лимит «Шторма».
- Клиент: форматирование времени, рендер таблицы «Время», экран финиша.

## Не делаем

- Отдельные призы за время: сезонные баллы пока не зависят от финиша.
- Серверная перепроверка заплыва.
