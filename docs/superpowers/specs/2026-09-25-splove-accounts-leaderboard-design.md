# СПLOVE: аккаунты, память и рейтинг

Дата: 2026-09-25
Статус: согласовано с заказчиком, готово к планированию

## Задача

Игра СПLOVE опубликована на GitHub Pages и работает как одиночная: счёт живёт
внутри вкладки, при закрытии пропадает. Нужно, чтобы друзья из чата сплава
играли под своими именами, результаты сохранялись, а после каждого заплыва
игрок видел своё место среди остальных.

## Решения, принятые на брифе

| Вопрос | Решение |
|---|---|
| Авторизация | Telegram |
| Формат | Mini App внутри Telegram, вне Telegram игра не открывается |
| Что помнится | Личные рекорды по уровням, история заплывов, накопительная статистика, выбранный трек |
| Метрика рейтинга | Лучший заплыв, три отдельные таблицы по уровням |
| Круг игроков | Только участники чата сплава, проверка через getChatMember |
| Бэкенд | Cloudflare Workers + D1 |
| Автопост в чат | Только при смене лидера на любом уровне |

Сознательно отвергнуто: прокачка байдарки за накопленные очки (ломает
сравнимость рейтинга), недельные таблицы (шесть таблиц на трёх уровнях),
общий открытый рейтинг, email-авторизация.

## Архитектура

Три части с узкими контрактами между ними.

### Игра (GitHub Pages, репозиторий splove-game)

URL не меняется: https://sorvalliny.github.io/splove-game/

Сейчас это один `index.html` на 488 строк. Разносится на нативные ES-модули
без сборщика — GitHub Pages отдаёт их как есть:

| Файл | Ответственность |
|---|---|
| `index.html` | Разметка экранов и стили |
| `js/engine/world.js` | Геометрия реки, физика байдарки, спавн объектов |
| `js/engine/render.js` | Рисование сцены на Canvas |
| `js/engine/audio.js` | Синтез музыки и звука через WebAudio |
| `js/engine/loop.js` | Игровой цикл, ввод, состояние заплыва, хуки наружу |
| `js/auth.js` | Telegram WebApp, получение initData и профиля |
| `js/api.js` | Клиент бэкенда: запросы, конверт ответа, ошибки, повторы |
| `js/store.js` | Локальный кэш профиля и таблиц, очередь неотправленных заплывов |
| `js/leaderboard.js` | Экран рейтинга |
| `js/screens.js` | Стартовый экран и экран «Без вёсел» |

Ограничение: ни один файл не превышает 300 строк. Движок сейчас занимает 397
строк (88–486) и в один файл не помещается, поэтому режется по границам,
которые в коде уже есть: аудио (~90 строк), мир и физика (~120), рисование
(~120), цикл и ввод (~70). Логика при переносе не меняется.

Два хука — единственная точка связи движка с новым кодом:
- `onRunStart({level, startedAt})`
- `onRunEnd({level, bank, onboard, meters, durationMs, oarsLost, startedAt, endedAt})`

`oarsLost` — сколько вёсел потеряно за заплыв суммарно, включая выловленные
обратно. Такого счётчика в движке нет, он добавляется одной строкой в
обработчике удара. Кроме него движок меняется ещё в двух местах: вызывает два
хука и отдаёт блок «рекорд сессии» из `gameOver` новому экрану. Больше ничего
в логике не трогается.

Значения приходят уже округлёнными до целых: `G.onb` внутри дробный, и SQLite
из-за слабой типизации примет дробь в `INTEGER`-колонку молча.

Движок не знает про сеть, авторизацию и рейтинг.

### Воркер (`worker/` в том же репозитории)

Один Cloudflare Worker обслуживает два входа:
- `/api/*` — запросы игры
- `/tg/webhook` — вебхук бота

Токен бота и идентификатор чата хранятся в секретах Cloudflare
(`wrangler secret put`), в git не попадают.

### База (Cloudflare D1)

Наружу не торчит, доступна только воркеру.

## Схема данных

```sql
CREATE TABLE players (
  tg_id             INTEGER PRIMARY KEY,
  name              TEXT NOT NULL,
  username          TEXT,
  photo_url         TEXT,
  is_member         INTEGER NOT NULL DEFAULT 0,
  member_checked_at INTEGER,
  track             TEXT,
  created_at        INTEGER NOT NULL,
  last_seen_at      INTEGER NOT NULL
);

CREATE TABLE runs (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  tg_id       INTEGER NOT NULL REFERENCES players(tg_id),
  level       TEXT    NOT NULL CHECK (level IN ('easy','normal','hard')),
  bank        INTEGER NOT NULL,
  onboard     INTEGER NOT NULL,
  meters      INTEGER NOT NULL,
  duration_ms INTEGER NOT NULL,
  oars_lost   INTEGER NOT NULL,
  rejected    TEXT,
  started_at  INTEGER NOT NULL,
  created_at  INTEGER NOT NULL
);

CREATE TABLE bests (
  tg_id      INTEGER NOT NULL REFERENCES players(tg_id),
  level      TEXT    NOT NULL,
  bank       INTEGER NOT NULL,
  meters     INTEGER NOT NULL,
  run_id     INTEGER NOT NULL REFERENCES runs(id),
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (tg_id, level)
);

CREATE INDEX idx_runs_player ON runs (tg_id, created_at DESC);
CREATE UNIQUE INDEX idx_runs_dedup ON runs (tg_id, started_at);
CREATE INDEX idx_bests_board ON bests (level, bank DESC, meters DESC, updated_at);
```

`bests` денормализован намеренно: рейтинг обслуживается одним индексным
запросом, без прохода по всей истории заплывов.

`runs.rejected` — причина отклонения, если заплыв не прошёл проверку
правдоподобия. Такие записи хранятся, но в `bests` и в рейтинг не попадают.

`runs.started_at` — время начала заплыва по часам клиента. На нём держатся две
вещи: ограничение частоты и защита от повторной отправки одного и того же
заплыва из офлайн-очереди.

Статистика профиля (всего заплывов, метров, потерянных вёсел) считается
агрегатом по `runs` на лету. При ожидаемых объёмах — десятки игроков, тысячи
заплывов — кэш не нужен.

## Авторизация

Своих сессий, паролей и JWT нет. Каждый запрос несёт заголовок
`X-Telegram-Init-Data` с подписанной строкой `initData` из Telegram WebApp.

Воркер на каждом запросе:
1. Считает HMAC-SHA256 по правилам Telegram (секрет — HMAC от токена бота с
   ключом `WebAppData`) и сверяет с `hash`.
2. Отклоняет, если `auth_date` старше 24 часов.
3. Апсертит игрока: имя, юзернейм, аватар, `last_seen_at`.
4. Если `member_checked_at` старше 24 часов, дёргает `getChatMember` для чата
   сплава. Статусы `creator`, `administrator`, `member` дают `is_member = 1`;
   `left` и `kicked` — ноль.

Игрок без членства в чате получает понятный отказ: игра открывается, но
результаты не сохраняются и рейтинг не показывается.

Подпись проверяется на каждом запросе, а не один раз при старте: initData
приходит бесплатно и это дешевле собственного управления сессиями.

## API

Все ответы в едином конверте:

```json
{ "ok": true,  "data": { }, "error": null }
{ "ok": false, "data": null, "error": { "code": "not_a_member", "message": "..." } }
```

CORS разрешён только для `https://sorvalliny.github.io`.

### POST /api/session

Вход: пустое тело, авторизация в заголовке.
Выход: профиль (имя, аватар, трек), личные рекорды по трём уровням с местом в
таблице, накопительная статистика.

Вызывается один раз при открытии игры.

### POST /api/runs

Вход: `{level, bank, onboard, meters, durationMs, oarsLost, startedAt}`.

Порядок: валидация схемы → проверка на повтор по паре (игрок, `startedAt`) →
проверка правдоподобия → запись в `runs` → обновление `bests`, если побит
рекорд → если игрок занял первое место на уровне, отправка сообщения в чат
внутри `ctx.waitUntil`, чтобы ответ игроку не ждал Telegram.

Рекорд считается побитым, когда пара (`bank`, `meters`) лексикографически
больше прежней: сначала сравнивается банк, при равном банке — метры. В таблице
действует тот же порядок, а полное равенство разводится временем: выше тот,
кто установил результат раньше. Поэтому ничья никогда не даёт двум игрокам
одно место, и заплыв с тем же банком, но большими метрами честно поднимает
игрока вверх.

Выход: место в таблице, дельта к личному рекорду, топ-20 уровня, флаг
`rejected` с причиной, если заплыв не засчитан.

### POST /api/board

Вход: `{level}`.
Выход: топ-20 уровня и строка самого игрока с его местом, даже если он вне топа.

### POST /api/profile

Вход: `{track}` — выбранный трек колонки на носу, одно из четырёх значений:
`chill`, `party`, `bard`, `off`. Всё остальное отклоняется на границе.
Выход: пустой.

Единственное, что игрок меняет о себе руками. Имя и аватар приходят из
Telegram и правке не подлежат.

## Защита от накрутки

Счёт считается в браузере, поэтому послать можно любое число. Полной
серверной перепроверки заплыва не будет — для игры на десять друзей это
несоразмерно по трудозатратам и риску сломать баланс.

Ставятся три барьера:

1. **Подпись Telegram** отсекает всех, кто не из чата сплава.
2. **Проверка правдоподобия.** Пороги выводятся из констант баланса:
   - Установившаяся скорость складывается из течения и гребли трёх вёсел с
     учётом множителя уровня (`speed`: 0.85 / 1.0 / 1.15) и бонуса капитана:
     `(40+30)·1.15 + 3·(44+16)·1.15·1.9 = 473.8` px/с, при `11·U` px на метр
     это 43.1 м/с. Текила добавляет разовый импульс, мгновенный пик доходит
     примерно до 57 м/с, но на средней за заплыв это почти не сказывается.
     Правило применяется к средней скорости и берётся с запасом:
     `meters <= 55 * durationMs / 1000`.
   - Потолок очков на метр. Бутылки спавнятся с фиксированным шагом
     `(300 + random·260)·U` px, одинаково на всех уровнях — минимум 27.3 м
     между ними. Дороже всего текила: 180 очков, с Геной 360. Это до 13.2
     очка на метр с одних пикапов, плюс до 3 за метры при обоих множителях.
     Стартовый порог берётся с двукратным запасом:
     `bank + onboard <= 30 * meters`. После первой недели калибруется по
     реальным заплывам.
   - `durationMs >= 5000`, все числовые поля целые и неотрицательные.

   Правила про потерянные вёсла нет намеренно: вёсла восстанавливаются
   пикапом, осмысленного потолка у этой величины не существует. Поле
   хранится как статистика и в проверках не участвует.
3. **Ограничение частоты.** Заплывы одного игрока не могут пересекаться во
   времени: `startedAt` нового не раньше, чем `startedAt + durationMs`
   предыдущего, с допуском в две секунды на расхождение часов. Это ловит
   попытку прислать десяток заплывов, «сыгранных» одновременно, и при этом не
   мешает честному быстрому рестарту — утонул на восьмой секунде и сразу
   поплыл заново. Сверху суточный потолок: 200 заплывов на игрока.

   Всё считается по `startedAt`, а не по времени прихода запроса: иначе пачка
   заплывов, накопленных на воде без связи, отклонится целиком.

   `startedAt` приходит с часов клиента, и на нём держатся оба механизма,
   поэтому он проверяется отдельно: метка не может быть в будущем больше чем
   на пять минут от серверного времени и старше тридцати суток.

   Повтор той же записи отсекается уникальным индексом по паре
   (игрок, `startedAt`): такой запрос возвращает прежний результат, а не
   ошибку — иначе офлайн-очередь будет ругаться на успешно отправленное.

Любой незасчитанный заплыв — и неправдоподобный, и нарушивший лимит — пишется
в `runs` с заполненным `rejected` и не влияет на рекорды. Ответ при этом
остаётся успешным конвертом (`ok: true`) с проставленным `rejected`: это
штатный исход, а не сбой. Ошибку конверта возвращают только отказ авторизации,
отсутствие членства в чате и битая схема запроса. Игроку показывается
«результат не засчитан» с причиной.

## Изменения в игре

### Стартовый экран

Строка «Авторская игра @sorval» заменяется на блок игрока: аватар, имя из
Telegram и одна строка смысла — «Твой рекорд на Сплаве: 340, третье место».
Экрана входа нет: Telegram отдаёт личность сам.

### Экран «Без вёсел»

К трём существующим цифрам добавляются:
- место в таблице уровня, на котором играл
- дельта к личному рекорду: «+80 к лучшему» или «не хватило 25»
- кнопка «Рейтинг»
- кнопка «В чат» — отправляет результат в чат сплава средствами Telegram

Строка про «рекорд сессии» убирается: сессия больше не единица памяти.

### Экран рейтинга

Новый экран, открывается автоматически после заплыва на вкладке того уровня,
где играл игрок. Три вкладки по уровням, топ-20 с аватарками, именами и
несгораемой суммой. Строка самого игрока прилипает снизу, если он вне топа.

Визуальный язык берётся существующий: Dela Gothic One, охра `#f4b41a` на
красной тени `#d9442b`, фон `#16262a`. Новых шрифтов и цветов не вводится.

### Поведение без сети

Игра обязана работать на воде, где связи нет.

- Заплыв, который не удалось отправить, кладётся в очередь в `localStorage`
  вместе со своим `startedAt` и уходит при следующем удачном запуске. Очередь
  отправляется пачкой; лимит частоты её не режет, потому что считается по
  времени заплыва, а не по времени запроса.
- Рейтинг показывается из последнего кэша с пометкой, на какое время данные.
- Ни один сетевой сбой не мешает играть: экран «Без вёсел» показывает цифры
  заплыва в любом случае.

## Бот

Живёт в том же воркере на `/tg/webhook`.

| Сценарий | Поведение |
|---|---|
| `/start` в личке | Кнопка «На воду», открывающая Mini App |
| Кнопка меню бота | Та же игра |
| «топ» в чате сплава | Текущие три таблицы сообщением в чат |
| Смена лидера | Бот пишет в чат: «Гена забрал Шторм: 520» |

Других автоматических сообщений бот не шлёт.

## Тестирование

Требование проекта — 80% покрытия. Тесты пишутся до реализации.

| Уровень | Что покрывается |
|---|---|
| Юнит | Проверка подписи Telegram: валидная, подделанная, просроченная, без hash. Правила правдоподобия на граничных значениях. Пересчёт рекордов и мест: побитый рекорд, равный `bank` с разными метрами, полное равенство с разным временем |
| Интеграция | Ручки API на живом воркере через `wrangler dev` с тестовой D1: новый игрок, не участник чата, побитый рекорд, отклонённый заплыв, пачка из офлайн-очереди, повторная отправка того же заплыва |
| Ручная проверка | Открытие Mini App в Telegram на телефоне, полный цикл от входа до места в таблице |

Геймплей автотестами не покрывается: Canvas и физика, тест стоит дороже, чем
ловит. Хуки движка при этом тестируются как обычные функции.

## Порядок работ

Четыре фазы, после каждой игра остаётся играбельной.

1. **Основание.** Воркер, D1, миграции, проверка подписи, `POST /api/session`.
   Результат: игра здоровается по имени.
2. **Память.** `POST /api/runs` и `POST /api/profile`, правила правдоподобия,
   `bests`, личные рекорды и статистика на стартовом экране, очередь отправки
   офлайн, запоминание трека колонки.
   Результат: рекорды переживают закрытие игры.
3. **Рейтинг.** `POST /api/board`, экран рейтинга, место и дельта на экране
   «Без вёсел». Результат: появляется соревнование, игру можно звать играть.
4. **Чат.** Бот, вебхук, команда «топ», сообщение о смене лидера, кнопка
   «В чат».

Друзья зовутся после третьей фазы.

## Что требуется от заказчика

- Аккаунт Cloudflare.
- Бот, созданный через @BotFather, и его токен. Токен кладётся в секреты
  Cloudflare, в репозиторий не попадает.
- Бот, добавленный в чат сплава, и идентификатор чата — без этого не работает
  проверка членства.

## Риски

| Риск | Смягчение |
|---|---|
| Порог очков на метр выбран неверно и режет честные заплывы | Стартовые 30 очков на метр взяты с двукратным запасом от расчётного потолка. Отклонённые заплывы сохраняются целиком, после первой недели порог калибруется по реальным данным и отклонённые пересчитываются |
| Telegram недоступен или сменил формат initData | Проверка подписи изолирована в одном модуле с тестами; отказ авторизации не мешает играть, только сохранять |
| Игра открыта вне Telegram | Показывается экран «Открой через бота» с ссылкой; игра в этом режиме не запускается |
| Рост числа игроков за пределы чата | Круг ограничен членством в чате, расширение — отдельное решение |
